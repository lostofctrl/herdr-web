# Browser-local file tabs use an opt-in confined file service

We will add file browsing and editing as browser-local tabs backed by an opt-in file service in the herdr-web bridge, rather than as shared Herdr tabs or unrestricted host filesystem access. This decision is accepted for the planned feature; it does not assert that implementation, rollout or validation is complete. Pi continues to use its real TUI and extension bridge as described in [ADR 0001](0001-pi-mode-terminal-mirror-plus-extension-bridge.md).

## Decision

- **Authority and trust.** File access is disabled until the operator configures a root. Allowed clients can read and write within the service's granted authority; there is no user authentication. Host and origin checks are not authentication, so a network-exposed bridge is suitable only for a trusted LAN, not an untrusted network. Listing exclusions and filename-based secret filters are not security boundaries.
- **Confinement.** Pin the configured root with an open directory descriptor and resolve operations relative to pinned directory descriptors, not by checking a path and later reopening it by name. Allow only relative symlinks whose resolution stays within the root; reject absolute links, magic links, escapes and failed resolutions. Reject kernel pseudo-filesystems such as procfs and sysfs, whose apparent files can expose process and kernel information, even when they are mounted within the root. This is not a guarantee that all accessed objects remain under the root's current pathname: if another local process moves an already pinned directory outside the root, its descriptor retains authority to that directory. Hard links inside the root can refer to the same inode as names outside it; their provenance cannot be established by path confinement.
- **Conditional saves.** Save against the revision read by the editor and report conflicts without discarding the draft. Coordinate cooperating bridge saves and recheck the destination before replacement, but an external non-cooperating writer can change the destination between the check and rename. Separately, a local writer with access to the destination directory can substitute the source temporary name before rename, causing a reported successful save to publish different data. This race is accepted within the local-writer trust boundary; neither conditional saves nor rename provide a universal compare-and-swap guarantee. Reject a save when visible metadata, ownership, permissions or hard-link identity cannot be preserved. **Accepted limitation:** an unprivileged Linux bridge may not be able to enumerate `trusted.*` extended attributes. Atomic replacement can lose those hidden attributes, potentially changing security or filesystem behavior; operators and users must be warned prominently.
- **Rename and delete races.** A concurrent local directory writer can replace a selected entry between the service's check and rename or delete, causing a different entry to be renamed or deleted. The operation remains anchored to its pinned parent directory; this entry-substitution race is explicitly accepted and is separate from the save races above.
- **Local tabs and drafts.** File tabs and their selection belong to the browser, not Herdr's shared tab or selection state. Bind each tab and draft to its bridge and root, not merely a reusable profile ID, and never silently restore them into a changed host or root. Preserve unsaved drafts through errors and external changes, warn before losing them, and offer discard. Browser storage may contain sensitive file content: make that risk visible and surface storage or quota failures while retaining the in-memory draft. After a bridge restart, quarantine old drafts until the user explicitly re-confirms the current root, since continuity across downtime cannot always be proved.
- **Pi mentions.** A file or line mention may be inserted only into an eligible Pi Pane on the same bridge host, selected explicitly with eligibility checked at action time. Insert into its Composer draft without submitting or running anything, preserve existing draft text, and reject stale or cross-host targets.
- **Git and previews.** Git features may use only explicitly authorized worktree and metadata roots, including any separate Git metadata directory. Enforce isolation against configuration, metadata and process access escaping those roots; if that isolation cannot be enforced on a platform, disable Git features there rather than falling back to unsafe execution. Treat file previews as untrusted: render content inertly or in a restrictive isolated sandbox with no application-origin or bridge API access and no unrestricted external resources.

## Considered Options

- **Shared Herdr tabs and selection:** rejected because browsing a file on one device would alter navigation for other clients and conflate browser state with Herdr workspace state.
- **Unrestricted or session-derived filesystem access:** rejected because a session reference or a path-prefix check does not establish confined authority and can expose unrelated files.
- **Unconditional saves or presumed atomic compare-and-swap:** rejected because they can silently overwrite changes or claim stronger protection against external writers than the filesystem operations provide.
- **Unisolated Git and active application-origin previews:** rejected because repository metadata, configuration and file content are untrusted and could escape the intended authority or reach bridge APIs.

## Consequences

- Operators must deliberately enable and secure the service; all allowed clients share its configured authority. Descriptor confinement reduces path traversal and replacement risks but does not protect against the moved-directory, hard-link or local-writer limits above.
- Clients must handle unavailable or changed bridge/root bindings, conflicts, storage failures and explicit root re-confirmation after restart. Persistent drafts improve recovery but leave potentially sensitive content in browser storage.
- Safe Git support can be unavailable on some platforms, and isolated previews may support less active content than unrestricted browser rendering. Implementation and security validation remain future work.
